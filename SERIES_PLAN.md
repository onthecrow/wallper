# Series: обои из нескольких обоев

> **Коротко.** Пользователь видит название «Series» (раньше в плане — «слайдшоу»). В коде данные — группа (`Wallpaper.Group`), движок — `SeriesWallpaperEngine`, спека — `WallpaperSpec.Series`.

## 1. Что делаем

> **Коротко.** Группа — это обои, которые по очереди показывают уже добавленные обои, каждые N времени. Создаётся из «+», редактируется из карточки. Сервис показывает группу составным движком, который меняет обычные движки.

- «+» на главной открывает диалог: «Видео или фото» (как сейчас) и «Слайдшоу».
- «Слайдшоу» открывает выбор из списка обоев. Отмеченные карточки подкрашены акцентным цветом, по центру у них иконка. Кнопка «ОК».
- Следующий экран — состав группы:
  - список горизонтальных строк, строку можно смахнуть, чтобы удалить;
  - «Добавить» возвращает к выбору;
  - выбор времени на одни обои;
  - «Сохранить».
- «Редактировать» на карточке группы открывает тот же экран состава.

## 2. Данные

> **Коротко.** Группа — строка в `wallpapers` плюс новая таблица участников с каскадным удалением. Схема v6, с миграцией и тестом.

- В `wallpapers` новая колонка `slide_duration_ms INTEGER`. NULL — не группа. У группы в ней время на одни обои (или 0 — «при каждом включении экрана», см. 7-3). Медиа-колонки группы хранят заглушки, как у встроенных.
- Таблица `wallpaper_group_items`:
  - колонки `group_id`, `wallpaper_id`, `position`;
  - PK `(group_id, position)`, индекс по `wallpaper_id`;
  - оба внешних ключа на `wallpapers(id)` с `ON DELETE CASCADE`.
- Что это даёт:
  - удалили обои — они сами пропали из всех групп;
  - удалили группу — её участники остаются;
  - редактирование и переход Media → ProcessedVideo сохраняют `id`, поэтому группа не теряет участника.
- Домен: `Wallpaper.Group(id, members, slideDuration, isActive)`. В группу не входят другие группы.
- Движку: `WallpaperSpec.Slideshow(slides: List<WallpaperSpec>, slideDurationMs)`. `ActiveWallpaperSourceImpl` собирает его из активной строки и её участников (`flatMapLatest`).
- Сценарии (use cases):
  - сохранить группу (новая становится активной, как в `SaveWallpaperUseCase`);
  - удалить группу (файлов у неё нет);
  - когда удаляются обои, пустые группы удаляются вместе с ними (7-8).

## 3. Сервис: как показывать группу

> **Коротко.** Рекомендую **A**: составной `SlideshowWallpaperEngine`, который по таймеру меняет обычные движки. Существующие движки не трогаем; смена слайда — резкая. Плавные переходы — потом, по варианту **C**.

### A. Составной движок (рекомендую)

- `SlideshowWallpaperEngine : WallpaperEngine` в `core:engine:impl`. Держит один дочерний движок; дочерние создаёт та же `WallpaperEngineFactory`: видео, оптимизированное видео, чёрная дыра.
- Когда и что показывать, решает чистый `SlideshowSchedule`:
  - считает только время, пока обои видны;
  - выбирает следующий слайд и пропускает сломанные;
  - тестируется на JVM виртуальным временем, как `EngineSupervisor`.
- Пересылает дочернему движку `onSurfaceChanged/Destroyed`, `pause/resume`, смещение страниц и zoom. Новому слайду сразу передаёт последнее смещение, как сервис в `dispatchOffsets`.
- Дочерний движок получает свой `EngineHost`. Если слайд сдался (`showPlaceholder`), он пропускается до конца сессии. Сдались все — заглушка через сервис.
- Смена слайда — тот же путь, что при выборе обоев пользователем. Старый движок отпускает поверхность синхронно (`gl.release(STOP_TIMEOUT_MS)`), потом создаётся новый. На экране последний кадр на мгновение замирает и сменяется резко (для видео ~0,2–0,5 с: подготовка плеера и EGL).
- Плюсы: мало кода, стабилизация (stall protection) каждого движка работает как есть, сервис почти не меняется.
- Минусы: нет перехода; передача поверхности, которая сейчас бывает только при выборе обоев, станет происходить каждые N секунд — гонки в ней станут заметны. Проверить первым делом, на нескольких устройствах.

### B. Один GL-движок, который сам смешивает слайды

- Один EGL-контекст на поверхности, каждый слайд — источник текстуры: видео через `SurfaceTexture` со своим плеером, чёрная дыра рисует в FBO. Переход — crossfade. Следующее видео готовится заранее.
- Плюсы: плавные переходы, поверхность никому не передаётся.
- Минусы: большая переделка:
  - чёрной дыре придётся отказаться от своего потока, `RestartableGl` и Choreographer-ритма;
  - на время перехода нужны два плеера сразу (память, нагрев);
  - стабилизацию придётся переосмыслить.
- Это недели работы.

### C. A, плюс crossfade между видео — следующим шагом

- `GLWallpaperEngine` получает второй видеоисточник: два плеера, две текстуры, один рендерер. Составной движок использует его для идущих подряд видео; между видео и чёрной дырой смена остаётся резкой.
- Делается поверх A, если резкая смена будет мешать.

### Отвергнуто: менять активные обои в базе по расписанию

Это запись в базу каждые N секунд, `activations` и пересчёт цветов. Сервис и так пересоздавал бы движок — то же A, только хуже.

### Цвета системы

> **Коротко.** Цвета считаем один раз, по первому слайду, и при смене слайда не обновляем.

`notifyColorsChanged` на Android 12+ перегенерирует палитру Material You, и это перетемивает лаунчер и приложения. Делать так на каждый слайд нельзя.

## 4. Модули

> **Коротко.** Новый feature-модуль не нужен. Данные и экраны — в `feature:wallpapers`, движок — в `core:engine`.

- Группа ссылается на строки той же базы: внешние ключи и каскад работают только внутри одной базы. `ActiveWallpaperSource` тоже реализует `feature:wallpapers`. Отдельной фиче понадобилась бы своя база без каскада или доступ к DAO чужой фичи.
- Экран выбора переиспользует `WallpaperCard`, а он `internal` в `wallpapers:ui-impl`. Отдельной фиче пришлось бы выносить его в `core:designsystem` вместе с `WallpaperItem` и строками.
- `core:engine:api` получает `WallpaperSpec.Slideshow`, `core:engine:impl` — составной движок. Core по-прежнему не знает фич.
- Если экраны групп разрастутся, вынести их в `feature:groups:ui-*` потом недорого.

## 5. UI

> **Коротко.** Один экран группы с двумя шагами (выбор → состав) и одной ViewModel: черновик живёт в ней, и не нужно передавать результат между экранами.

- `Navigator` умеет только `navigate`/`navigateBack`, результатов у него нет. Поэтому:
  - `GroupEditorDestination(groupId: Int?)` — одна ViewModel и два шага;
  - новая группа начинается с выбора, существующая — с состава;
  - «Добавить» на шаге состава возвращает к выбору с уже отмеченными участниками.
- Выбор: сетка как на главной; отмеченная карточка с тинтом `primary` и иконкой по центру. Группы в выборе не показываются.
- Состав:
  - строки: картинка на всю ширину строки, обрезанная по центру, и плашка карточки с главной справа снизу;
  - `SwipeToDismissBox` для удаления;
  - внизу подложка: выбор времени и «Сохранить»;
  - в конце списка кнопка «+ Add wallpaper», как «Add currency» в NomadRates: пилюля в конце списка, при прокрутке прилипает к верхнему краю подложки и морфится в круглый «+».
  - «Сохранить» недоступна, пока участников меньше двух (7-11).
- Карточка группы на главной:
  - миниатюра первого участника, плашка «Series»;
  - «Редактировать» открывает состав;
  - «Удалить» спрашивает подтверждение и удаляет только группу.
- Диалог «+»: две кнопки, `AlertDialog` или нижний лист.

## 6. Порядок работ

> **Коротко.** Данные → движок → экраны. Каждый шаг со своими тестами.

1. Схема v6: колонка, таблица участников, миграция и тест, маппер, `Wallpaper.Group`, `WallpaperSpec.Slideshow`, сборка спеки активной группы.
2. `SlideshowSchedule` с JVM-тестами, `SlideshowWallpaperEngine`, ветка в `WallpaperEngineFactory`, цвета по первому слайду.
3. Диалог «+», экран группы (выбор и состав), карточка группы, удаление пустых групп.
4. CLAUDE.md: раздел про группы.
