## 4. Главные разногласия
1. **TL-4: качество по умолчанию.** Иду против решения владельца сознательно.
   - Владелец выбрал HIGH из-за того, что старый Auto ронял OnePlus на Low. Новое правило шагает вниз только при нагрузке выше 1 (мс GPU × fps).
   - На его OnePlus это 7.6 мс × 60 ≈ 0.46 и 7.6 × 30 ≈ 0.23. AUTO там остаётся на HIGH, разницы владелец не увидит.
   - На слабом GPU AUTO спасает от перегрева, а HIGH фиксирован навсегда: понижение происходит только на время нагрева.
   - Предложение: AUTO по умолчанию. Если владелец настаивает на HIGH — хотя бы отключить GPU-таймер вне AUTO (DEV-13) и включить `powerSaveStill`.
2. **TL-8: экран настроек.** Резать до 8 контролов против явного запроса владельца не стоит: это продуктовое решение, и он принял его сознательно. Инженерная часть решается без потери функций:
   - группы «Основное» и «Тонкая настройка» (вторая свёрнута);
   - HUD только в debuggable-сборке;
   - один источник диапазонов (`STAR_COUNT` уже разошёлся);
   - хранение через JSON (TL-9), чтобы новая настройка не требовала 9 правок;
   - пейсинг превью (DEV-16).
3. **ARCH-3, ARCH-4, ARCH-5 как major.** Для одной встроенной обоины это YAGNI; я за minor.
   - ARCH сам откладывает ARCH-3 до вторых обоев.
   - По ARCH-4 полезная часть — модель настроек в JVM-модуле; новый модуль не нужен.
   - По ARCH-5 нарушений сегодня нет.
   - Реальные баги (DEV-1, DEV-2, TL-5) сидят в Android-обвязке движка, а не в раскладке модулей. Их чинит ARCH-1 с тестами, а не ARCH-3.
4. **TL-2 как blocker.** WIP-коммит сегодня — да. Разбиение на четыре PR через `git add -p` по `BlackHoleSettings.kt` — непропорционально для соло-проекта до релиза. Нужны два-три коммита, с отдельным коммитом для изменения `core:gl`, которое меняет видео.
