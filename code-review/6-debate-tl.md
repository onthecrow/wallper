## 4. Главные разногласия

1. **С DEV: «блокеров нет».** Не согласен. TL-2 блокирует мерж: один снимок на ~130 файлов, правка `core:gl` для видео тонет в чёрной дыре. TL-1 блокирует релиз. Без TL-3 все находки DEV-1, -2, -5, -7 в проде невидимы.
2. **С ARCH: ARCH-3, ARCH-4 и ARCH-5 как major и в топ-5 выше релизных рисков.** Встроенные обои одни, разработчик один. Новые модули (`core:scene`, `core:blackhole:data`), Konsist и инвертированный allowlist — это работа на будущее, которого ещё нет. Сейчас — только дешёвое: цвета из ARCH-6, правило «impl только для `:app`», `internal` на классах `-impl`.
3. **Объём рефакторинга движка (ARCH-1 и DEV-6).** Предлагаю порядок:
   1. Проверить DEV-7 на устройстве.
   2. Точечно починить DEV-1 (опираться на `pacedFps`) и DEV-2 (teardown на потоке колбэков; рестарт, только если старый поток реально вышел).
   3. Чистая функция решений пейсинга с JVM-тестами.
   4. Один общий супервизор GL для двух движков.

   Порт `BlackHoleFrameLoop` из ARCH-1 — нет: это два новых уровня абстракции ради одного класса.
4. **С владельцем: HIGH по умолчанию.** Спорю осознанно.
   - После перекалибровки AUTO — это «старт с High, вниз только при перегрузке GPU».
   - По данным PLAN, на OnePlus HIGH занимает ~7.6 мс, нагрузка при 60 fps ≈ 0.46. Значит, AUTO там остаётся на High и ничего не стоит, а слабые GPU защищает.
   - Риск остаётся один: без GPU-таймера AUTO сейчас уходит на Medium. Лечится так: при отсутствии таймера держать стартовый уровень и полагаться на thermal.
   - Если владелец всё же оставляет HIGH, тогда включить шаг вниз при перегрузке и для HIGH — фактически это сделать HIGH текущим AUTO.
